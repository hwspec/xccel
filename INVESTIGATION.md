# xccel

Our goal is to develop programmable detector ASICs for X-ray science.


## Target Applications

Assumes running inference of these X-ray AI models.

### [BraggNN](https://github.com/lzhengchun/BraggNN)

- localizes Bragg peak in a patch (dividing single image to some patches is not responsibility of this model, so it can assume that the input data is devided to, for example, 11x11 pixel patches holding only one peak).
- light-weight CNN model that consists of three convolutional layers, non-local attention block, and four fully-connected layers.
- includes Conv, Reshape, Transpose, Matmul, Softmax, LeakyRelu, Add, and Gemm
- ultimately, require to achieve 1 μs latency.
- for batch inference because a large number of patches that generated by other ICs from single senser data are fed into the accelerator in a streaming manner.

### [PtychoNN](https://github.com/mcherukara/PtychoNN)

- predicts sample amplitude and phase from diffraction data.
- two-headed encoder-decoder model that consists of basically convolutional layers, max pooling, and upsampling.
- includes Conv, Relu, MaxPool (we should focus on only encoder part and amplitude head to offload to accelerators).
- for single batch inference.

### Roofline Model

We analyzed theoretical floor of Gemmini performance using the Roofline model.
Delm et.al. proposed the configuration-wall in AI accelerators as an analogous of memory-wall [[2]](#2).
Therefore, we apply this model to each kernel in BraggNN based on Gemmini architectual restrictions.

Here are formula and theoretical floor of whole program, not per-kernel (note that it does not care about inter/intra-kernel memory access).

$$
P_{Attainable,\ Seq.} = \frac{1}{\dfrac{1}{\min\{P_{Peak},\ BW_{Memory}\times I_{Operational}\}}+\dfrac{1}{BW_{Conf.}\times I_{OC}}}
$$

- $P_{Peak}=16\cdot16\cdot2=512\ \text{ops/cycle}$

- $BW_{Config}=\dfrac{16}{3\cdot3}\approx 1.77\ \text{bytes/cycle}$
  - From the paper, assume 3 configuration instructions consuming 3 cycles per instruction

- $I_{OC}=\dfrac{524{,}288}{77}\approx6{,}809\ \text{ops/bytes}$
  - Table 1 shows each bit per configuration field. 77 byte is the sum of each field.
  - Configuration field depends on operation and matrices' size

- $BW_{Memory}=16\ \text{bytes/cycle}$
  - `dma_buswidth=128` from Gemmini source

- $I_{Operational}=\text{ops/byte (input+weight+bias+output)}$

- E.g., $P_{Attainable,\ Seq.} = \dfrac{1}{\dfrac{1}{512}+\dfrac{1}{12052}}\approx 491\ \text{ops/cycle}$
  - In case of removing memory access
  - Compute-bound
- Don't care of activation including ReLU
- Cycles (whole program, not per-kernel): 1068
- Time @ 1.5GHz (us): 0.71

### Discussin

- The stall at Scratchpad feeding operands in the mesh dominates the large portion of cycles.
- The sum of all `exe_active` in the hardware counters table is 17,067, minimum cycles when we eliminate all memory-bound cycles but don't change compute units and tiling strategies.
- The fact that most of the M/N/K sizes are not multiple of DIM (=16) makes tiling strategies difficult.
- Resadd operation takes a large number of DMA cycles


## Existing Accelerators

### Gemmini

- Co-processor accelerator has systolic array with large single Scratchpad.
- Programmable but too slow.
- It does not fit to tiny matrix-multiplication because of introducing SRAM stalls.
- Scratchpad has only four banks and single port.
- Every inter-kernel result is written back to the DRAM from accumulator.
- I-BERT unit overflows internal registers because of very small quantized parameters.
- Sequential configuration instruction introduces configuration-wall.

- Data movement from the detector to downstream Groq becomes the bottleneck.

## Concept of Our Accelerator

Firstly, we shall resolve these partial problems in our design.

- Eliminating DRAM round-trip
- Eliminating SRAM stalls
- Designing to fit to both tiny kernels in BraggNN and large convolution with max-pooling in PtychoNN

Here are some features we want

- Input data are fed from streaming of the censor to the mesh directly via queues
- Deterministic dataflow
- Variable systolic dimentions
- Separated high-bandwidth SRAMs; one for per-kernel output, and another for next kernel input
- No ROB, Reservation Station, and arbiter
- Im2col, normalizer, requantizatin units
- Native residual add support
